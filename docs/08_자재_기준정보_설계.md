이 문서는 자재 목록 엑셀 `docs/references/mat/자재목록_분류별14시트.xlsx` 를 분석해서 품목 마스터의 테이블 구조, 가져오기 규칙, 검색 방식을 정합니다. 코딩은 보류 중이라 SQL은 초안으로만 담았고 마이그레이션 파일은 만들지 않았습니다.

**표기**: ✅ = 엑셀에서 확인한 사실. ⏳ = 확인이 필요해서 기본값으로 둔 부분이고 괄호는 `question-공통.md`의 질문 번호입니다.

## 2. 설계 결정

| 주제 | 결정 | 상태 |
|------|------|------|
| 품목의 단위 | **(자재명 + 규격)이 한 품목.** 규격을 열로 쪼개 별도 품목으로 만들지 않고, 규격마다 품목 한 줄을 둔다 | ✅ 엑셀이 이 구조 |
| 규격 저장 | **원문(`spec`)을 그대로 저장.** 408가지 패턴을 정규화하려 하지 않는다 | ✅ |
| 검색용 파생값 | 관경(`nominal_a`)만 파생 열로 추출. 그 외(압력등급, 길이)는 원문에서 검색 | ⏳ 8.1 |
| 분류 | 엑셀 시트 14개를 `category` 14개로 옮긴다. 분류는 한 품목에 하나 | ✅ 시트 간 중복 0 |
| 품목 코드 | 시스템이 자동 부여 (`분류 2자리-일련번호 5자리`, 예: `02-00123`). 기존 코드가 있으면 `legacy_code`에 보관 | ⏳ (공통-21) |
| 단가 | 품목 마스터에 두지 않는다. 단가는 별도 `item_price`(공급사·적용일 이력) | ✅ 엑셀에 단가 없음 |
| 단위 | `unit` 표를 두고 16종을 등록. 품목은 단위 코드를 참조 | ✅ |
| 단위 환산 | `conv_unit`·`conv_rate`는 필요한 품목만 (덕트 m²↔kg, 관 본↔m) | ⏳ 8.2 |
| 삭제 | 품목은 지우지 않고 `active=false`로 숨긴다 (이미 발주·출고에 쓰였을 수 있음) | ✅ 원장 불변 원칙 |
| 이름 중복 방지 | `(name, spec)` 유일 제약 | ✅ 엑셀 중복 0건 |

## 3. 테이블 (초안)

### 3.1 분류와 단위

```sql
-- 초안: 마이그레이션 파일이 아님
create table item_category (
  id        smallint primary key,
  code      char(2) not null unique,        -- '01'..'14'
  name      text not null,                  -- 화면 표시 이름
  sheet_src text,                           -- 엑셀 시트 원문 이름 (가져오기 추적용)
  sort      smallint not null default 0,
  active    boolean not null default true
);

create table unit (
  code   text primary key,                  -- '개','m','본','세트','롤','대','켤레','캔','벌','자루','장','통','조','kg','쌍','㎡'
  name   text not null,
  kind   text not null check (kind in ('COUNT','LENGTH','AREA','WEIGHT','VOLUME'))
);
```

### 3.2 품목

```sql
create table item (
  id           bigint generated always as identity primary key,
  code         text not null unique,        -- 시스템 부여 (예: '02-00123')
  legacy_code  text,                        -- 기존 코드가 있을 때만
  category_id  smallint not null references item_category(id),
  name         text not null,               -- 엑셀 '자재명' 원문
  spec         text not null,               -- 엑셀 '규격' 원문
  unit_code    text not null references unit(code),
  nominal_a    integer,                     -- 관경(A). 규격에서 추출, 없으면 null
  base_name    text not null,               -- 괄호 앞 기본명 (검색·그룹용)
  active       boolean not null default true,
  created_at   timestamptz not null default now(),
  unique (name, spec)
);

create index item_category_idx on item (category_id);
create index item_base_name_idx on item (base_name);
create index item_nominal_idx on item (nominal_a);
create index item_name_trgm on item using gin (name gin_trgm_ops);   -- 부분 일치 검색 (pg_trgm)
create index item_spec_trgm on item using gin (spec gin_trgm_ops);
```

- `base_name`은 `자재명`에서 첫 `(` 앞부분을 잘라 만듭니다(예: `익스팬션조인트(…)` → `익스팬션조인트`). 규격만 다른 같은 계열을 묶어 보여 줄 때 씁니다.
- `nominal_a`는 규격에서 첫 `NNA` 패턴을 추출해 채웁니다. 이경 부속(`50A × 25A`)은 큰 쪽을 넣습니다(8.1).
- 전체 검색은 PostgreSQL `pg_trgm` 확장을 씁니다. 15,339건은 인덱스만으로 충분히 빠릅니다.

### 3.3 단위 환산과 단가 (후속)

```sql
create table item_conversion (            -- 환산이 필요한 품목만
  item_id   bigint primary key references item(id),
  to_unit   text not null references unit(code),
  rate      numeric(18,6) not null check (rate > 0),   -- 1 [item.unit] = rate [to_unit]
  note      text
);

create table item_price (                 -- 단가 이력. 06 문서 견적·발주에서 참조
  id            bigint generated always as identity primary key,
  item_id       bigint not null references item(id),
  partner_id    bigint,                   -- 공급사 (null = 기준 단가)
  kind          text not null check (kind in ('STANDARD','ACTUAL','PURCHASE')),
  unit_price    bigint not null check (unit_price >= 0),   -- 원, 부가세 별도
  effective_from date not null,
  source        text,
  created_at    timestamptz not null default now()
);
```

금액은 `bigint`(원)입니다(규칙 3). 단가 이력은 추가만 하고 고치지 않습니다. 이 표의 모양은 07 문서 4.1의 `unit_price`와 합쳐 하나로 정리해야 합니다(8.5).

## 4. 엑셀 가져오기

### 4.1 규칙

1. 시트 순서(`01`~`14`)가 분류 코드가 됩니다. 시트 이름에서 앞 두 자리를 분류 코드로, 나머지를 `sheet_src`로 저장합니다.
2. 각 시트의 첫 행은 머리글이고 `자재명 · 규격 · 단위` 세 열이어야 합니다. 다르면 시트 이름과 함께 거부합니다.
3. 각 행: 앞뒤 공백을 지우고, 세 열이 모두 비어 있으면 건너뜁니다. 자재명·규격·단위 중 하나라도 비어 있으면 행 번호와 함께 거부합니다.
4. 단위가 `unit`에 없으면 거부하고 보고합니다(새 단위는 사람이 먼저 등록).
5. `(name, spec)`이 이미 있으면 새로 만들지 않고 건너뜁니다. 같은 파일을 두 번 가져와도 결과가 같습니다(멱등).
6. 이미 있는데 단위가 다르면 덮어쓰지 않고 차이 목록으로 보여 줍니다.
7. 가져오기는 한 트랜잭션입니다. 하나라도 거부되면 아무것도 저장하지 않고, 오류는 시트·행 번호와 함께 모아서 보여 줍니다.
8. 코드 부여: 분류별 일련번호를 시트 순서대로 부여합니다. 엑셀 행 순서가 바뀌어도 코드가 달라지지 않도록, 한 번 부여한 코드는 `(name, spec)`에 고정합니다.

### 4.2 이 엑셀로 검증할 수 있는 항목 (필수 테스트)

| 경우 | 기대 |
|------|------|
| 이 엑셀을 처음 가져오기 | 품목 15,339건, 분류 14건, 단위 16종 |
| 같은 파일을 한 번 더 가져오기 | 추가 0건, 오류 없음 |
| 시트 머리글이 `자재명, 규격, 단위`가 아님 | 시트 이름과 함께 거부 |
| 빈 규격 행이 섞임 | 행 번호와 함께 거부, 전부 롤백 |
| 새로운 단위(`박스`)가 나옴 | 거부, 사람이 단위를 먼저 등록 |
| 같은 `(name, spec)`에 다른 단위 | 덮어쓰지 않고 차이로 보고 |
| `50A × 25A` 규격 | `nominal_a = 50` |
| `6A / STS304 / SCH10S / 1.2T` 규격 | `nominal_a = 6` |
| 관경이 없는 규격 (`H21`, `AG-1119 / 300mL / 회색`) | `nominal_a = null` |
| `익스팬션조인트(플랜지)(…)` | `base_name = 익스팬션조인트` |
| 괄호가 없는 자재명 | `base_name`은 자재명 전체 |

## 5. 검색과 화면

| 화면 | 사용자 | 핵심 |
|------|-------|------|
| 품목 검색 | 견적·구매·현장소장 | 분류 선택 → 기본명 → 규격 순으로 좁히기. 자재명/규격 부분 일치(pg_trgm). 관경 필터(15A~300A). 15,339건이므로 목록 가상 스크롤 필요 |
| 품목 상세 | 구매 | 분류, 단위, 단위 환산, 최근 단가 이력, 사용된 발주·출고 |
| 품목 추가·수정 | 구매·관리자 | 이름·규격 유일 검사. 이미 거래가 있는 품목의 이름·규격·단위는 수정 불가(새 품목으로) |
| 가져오기 | 관리자 | 파일 선택 → 미리보기(추가·건너뜀·오류 건수) → 확정 |

현장소장이 모바일에서 자재를 청구할 때는 "기본명 → 규격" 두 단계로 고르게 합니다. 15,339건을 한 번에 보여 주지 않습니다.

## 6. 다른 모듈과의 연결

- **견적(07 문서)**: `estimate_item.item_id`가 `item.id`를 참조. 견적에서 품목을 고르면 최근 단가를 옆에 참고로 보여 줍니다.
- **자재 청구·발주·입고·출고(06 문서)**: `material_request_line`, `purchase_order_line`, `goods_receipt_line`, `stock_tx`가 `item.id`를 참조합니다.
- **모듈 경계**: 품목 마스터는 `mdm`이 소유하고, `mat`·`sal`은 `mdm` 서비스 인터페이스(`mdm.FindItem`, `mdm.SearchItems`)로만 읽습니다. 다른 모듈이 `item` 테이블을 직접 조회하지 않습니다(CLAUDE.md 규칙 1).
- **품목 사용 중 삭제 방지**: 발주·출고에 한 번이라도 쓰인 품목은 `active=false`만 가능합니다.

## 7. 권한과 감사

- 품목 조회는 전 직원. 추가·수정·비활성화는 구매·관리자만.
- 단가(`item_price`) 조회는 구매·견적·임원만. 현장소장에게는 품목과 수량 중심 화면을 보여 줍니다(01 설계서 6장).
- 감사 로그(규칙 6): 품목 추가·수정·비활성화, 대량 가져오기(건수 포함), 단가 변경.

| 6 | 엑셀에 없는 품목(장비, 덕트 부속, 전기 자재 등)은 어떻게 등록하나 | 구매·견적 | 화면에서 한 건씩 추가, 대량은 같은 형식 엑셀로 |
| 7 | 단가표는 따로 있는가 (공급사별인지, 기준 단가인지) | 구매·견적 | 별도 파일을 받으면 `item_price`로 가져오기 |
| 8 | `15,339건` 중 실제로 자주 쓰는 품목은 얼마나 되는가 (자주 쓰는 품목을 먼저 보여 줄지) | 구매·현장 | 사용 빈도 자동 집계 후 상단 표시 |

질문 1~8은 `question-자재기준정보.md`로 정리해 담당자에게 보냅니다.
